# 追加：Qsight 的 Prompt 调整后的结果

接着 `QSIGHT_PROMPT_LIGHT.md` 继续，在分支 `redesign/qsight-prompt` 上提交，不开新分支。在 `qsight.ts` 里新增一个 subsection，并对上线反馈做一处删减（见下），其他内容不动。

## 位置

放在 `qsight-04` 里 Prompt 这一块的最后：即"用编译器写各章的 Prompt"之后、下一章"上线后的反馈与记录"（`qsight-05`）之前。

如果"用编译器写各章的 Prompt"因为【待填】未填已被删除，就放在"一个章节的 Prompt 里写了什么"之后。

## 为什么加

前面讲了 Prompt 怎么设计、怎么防出错，读者还不知道用了以后三个问题有没有改善。这一节回答这个。

同事试用时的口头反馈，聊天记录已经找不到了；但用同一组数据维度做的调整前后对比是有记录的。所以这一节写两样：对比的结果，和本人看日志、试用时看到的变化。

## 新增 subsection：`调整后，三个问题有没有改善`

文案逐字使用。

`paragraph`：
调整后由业务和测试同事试用，也给了口头反馈。下面写的是同一组数据维度的前后对比，和我看日志、试用时观察到的变化。

`table`（label：`三个问题调整前后的变化`，headers：`问题`、`调整前`、`调整后`）：

| 问题 | 调整前 | 调整后 |
|---|---|---|
| 内容跑偏 | 每次产出的结构都不太一样 | 结构是固定的，内容能对应到数据 |
| 跳过该用的工具 | 模型有时跳过应调用的工具 | 工具调用很准确，基本没有跳步 |
| 编造数据 | 模型会编造没有依据的数据 | 编造的情况很少见，数据基本都能找到来源 |

`paragraph`：
同一组数据维度，调整前后各生成一遍报告来对比。调整前，报告里没有标注来源；调整后，关键事实都标上了来源，通过率基本能到 80% 以上。【待填：样本数量、统计时间，以及通过的标准】

`paragraph`：
看日志，每次基本都是按四个步骤执行的。还有两处没解决：自检这一步偶尔不靠谱；当时用的检索工具质量一般，会混进不相关的信息。

`paragraph`：
当时我想到的下一步，是加一个小的评测模型，专门看章节智能体有没有跑偏。它标出哪里跑偏，我就知道该改 Prompt 的哪一段。2026 年 5 月项目结束，这件事没有往下做。

## 不要做的

- 只允许出现一个数字：「80% 以上」。对比是有记录的，不要写"没有留存记录""估算"这类话；样本数量等细节用上面的【待填】。不写其他数字、百分比、耗时，也不写「约 50%」这类调整前的数字。
- 不写"不再编造""完全解决"这类绝对的话；表格里"编造的情况很少见"逐字使用。
- 不把"2~3 天缩短到约 20 分钟"之类整个产品的效果算到 Prompt 上。
- **上线反馈一章（`qsight-05`）做一处删减**：删除"关键事实溯源"这一组（标题、"约 50% → 80%"和它对应的【待填：关键事实的定义……】），因为这个结果已经放到上面这一节。把该章引言改为：`1.0 已上线。试点阶段记录了整体交付和分阶段耗时，统计样本与口径仍待补充。` 整体交付耗时、分阶段耗时两组及其【待填】原样保留，其他内容不动。
- 不提裁员。
- 不新增图片和组件；表格用现有的 `table` 块。
