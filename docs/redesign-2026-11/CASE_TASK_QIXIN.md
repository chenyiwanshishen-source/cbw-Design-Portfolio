### CaseSummary
- 问题：功能越加越多，用户的工作路径被拆散；本地产业链每次都要内部配置，用户只能等。
- 方案：按任务重组首页和功能；把产业链配置交给用户；用组件库保证长期一致。
- 结果：本地产业链构建周期 1–2 周 → 2–3 天

### 01 · 挑战
**H2：** 功能越加越多，用户的工作路径反而被拆散了

> 数据与功能分散，用户很难连续完成定位范围、筛选目标、判断价值、跟进管理和输出结果。问题不在缺少某个功能，而在工作路径被拆散。

### 02 · 定义问题
**H2：** 五类用户，走的是同一条任务路径

`DataTable`：

| 场景 | 典型用户 | 核心任务 |
|---|---|---|
| 招商 | 招商办、园区招商人员 | 找产业、找企业、建名单、跟进线索 |
| 产业服务 | 产业部门、园区运营 | 看产业结构、服务本地企业 |
| 企业服务 | 企业服务部门 | 看企业画像、识别风险、跟踪成长 |
| 金融 | 银行、投资机构 | 企业筛选、风险判断、价值评估 |
| 区域治理 | 区域经济管理者 | 看区域经济、迁入迁出、输出报告 |

> 五类场景共享同一条路径：定位范围 → 筛选目标 → 判断价值 → 持续管理 → 输出结果。我以招商为主场景画了体验地图。

### 03 · 产业链配置
**H2：** 把产业链配置，从内部交付改成用户自己维护

> 每个地区对产业链怎么划分、哪些企业算本地特色，理解都不一样。以前用户提需求后，要等我们梳理结构、开发配置，改一次再等一轮。我判断标准环节可以复用，差异只在本地口径，所以把配置能力做成产品：标准环节直接选用，没有的环节自己新建，节点关系和企业名单由用户维护。

**H2：** 首页从"找功能"改成"接任务"
